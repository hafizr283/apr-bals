# New external comparison protocol

Inputs: approximately 70% train, 10% validation, 20% preserved original test. Absolute test values are reported separately from target-RMSE curves. All methods in the external figure see the **same warm-validation subset**: exclude ratings where either entity has zero training observations. Training is unchanged by this evaluation mask. Each dataset's `external_inputs/*/manifest.json` records removed and retained counts.

APR uses the new validation-selected lambda, beta=.3, FP32 solvers below K96 and FP16 tiled solver at K96. Both training and validation RMSE are checked in FP32 every sweep. Training is continued for 30 sweeps to supply full curves; crossing is derived afterward from the validation target, never from test results.

cuMF-ALS retains the existing CUDA-12 port: generic cusparseSpMM replaces removed csrmm2; buffers live outside the timed loop; the original test-grid tail bug is fixed. FP16 operand and CG-matrix switches are **off**. It uses six CG steps, X_BATCH=1 and THETA_BATCH=3, the existing configuration rather than a new batching/stream tuning search. The input orientation is items x users. New local changes: evaluate every sweep; log cumulative elapsed wall time; use double accumulation for the RMSE error reduction; zero factors for empty training entities after each CG batch, before the next phase can consume them. The training kernels otherwise remain unchanged. This guarded port must be named in the paper; it is not the untouched upstream executable.

CCD uses the same ranks as APR. Select its separate lambda convention from {.02,.04,.05,.058,.08,.12} using warm-validation RMSE at K96/sweep30. Keep that chosen lambda across ranks. `-T 1`, tiles a=b=100000, 30 outer sweeps. New local changes: cumulative training-loop wall timing at every existing held-out evaluation, and double host summation of per-rating squared errors. Its old `iter ... time` field is accumulated compute time and is NOT the new headline timer.

SGD uses rank128 and its published local recipe lambda=.05, alpha=.08, beta=.3, workers 256/384/512/512, 40 epochs. These are prespecified settings, not newly validation-tuned SGD parameters. The update equation, FP16 factors, worker count and learning-rate schedule are unchanged. For a continuous accuracy-time curve, launch the same update kernel for one epoch at a time with `current_iter` advanced, retaining factors and RNG state. This introduces a global synchronization between epochs relative to the original persistent multi-epoch launch. A GPU evaluator uses the same ID permutation and rating scale as training, checks validation after every epoch, and accumulates squared errors in FP64. GPU random seeds are fixed to 20261014, but Hogwild races still make trajectories nondeterministic. The final curve value is cross-checked against the saved-model CPU predictor. This instrumentation adds evaluation and launch overhead; do not silently substitute these timings for the old persistent-kernel timings.

BALS uses the existing local reimplementation with frequency reordering, identical initialization scale and weighted lambda to APR, FP32 arithmetic, no momentum, and exact RMSE every sweep. It is not independently released BALS code. The default reorder-only mapping is used consistently rather than choosing the faster mapping separately from each measured run.

All four rank-dependent systems use K/F pairs (16,20), (32,30), (48,50), (64,60), (96,100); SGD is compared only with APR K96. Cold-start accuracy is not claimed from the warm-validation figure. Uniform zero fallback on full test ratings is reported separately when available. Exclude no non-finite warm predictions silently.

Training-loop wall includes each method's own evaluation implementation. APR/BALS/ALS also compute training RMSE, whereas CCD/SGD evaluate held-out RMSE only; this overhead difference must be disclosed. New timings are single runs. New repeated runs are needed before claiming sub-percent differences or attaching the historical paired-harness variance to these results.

Execution update: at the user's request, external measurements remain on GPU1 while independent numerical/accuracy diagnostics run on GPU0. Both devices are RTX3060, but GPU0 also serves the desktop. GPU0 diagnostic times are not compared as performance results. Shared-host CPU, memory, and PCIe contention may affect GPU1 wall timings; these concurrent-run conditions must accompany the external timing results.

Entity ordering: the validation split retains the original preprocessed IDs rather than sorting entities again. APR derives dense/giant prefix lengths from new training degrees, but random validation removal can disturb the original degree order. Thus these runs use the shipped contiguous-prefix dispatch, not a guarantee that every entity in a prefix exceeds its threshold. `dispatch_audit.json` quantifies the mismatches (e.g. ML32M item dense prefix contains 1,984 entities below 4 ratings, while 2,010 qualifying items remain in the scalar suffix; Netflix giant-user prefix has 63 below 1024 and 63 qualifying users outside). All entities remain covered exactly once by the disjoint prefix/suffix paths; this is a dispatch-efficiency/precision-routing limitation, not omitted training rows. A fresh degree sort would be a separate protocol/configuration requiring new timing and accuracy runs.
